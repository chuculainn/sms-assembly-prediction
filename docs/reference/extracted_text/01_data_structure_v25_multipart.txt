1 修订目标与原则

本修订用于使数据结构同时满足多零件拓扑表达、多接口统一接触求解、阶段状态继承、JOIN 锁定/

RELEASE 回弹以及最终 KCP 贡献重构。

  拓扑唯一：零件是节点，接口和连接是边，装配步骤具有独立 topology_step_id。

  向量可解释：所有全局向量和矩阵必须引用 VectorLayout，禁止仅靠隐含顺序解释。

  状态可继承：聚合快照、零件快照和接口快照必须有父状态链。

  耦合可验证：W_struct 的接口交叉块必须保存并纳入质量门。

  贡献不重复：每个零件 SMS 只登记一次；每个接口阶段增量只登记一次。

  真实性分级：本案例明确为合成数值一致性数据，不得替代工程 FE、测量或试验数据。

AssemblyTopology 的主键由原来的 topology_id 扩展为 topology_step_id；topology_id 表示同一装

activated_interface_ids 中同时列出，不能拆成互相独立的两次求解。

对角块表示接口自身柔度，非对角块表示共享零件和装配闭环引起的跨接口影响。本案例四个阶段的六

对非对角接口块均非零。

 0 <= lambda^(s) perpendicular g^(s) = q^(s) + W_total^(s) lambda^(s) >= 0

6 多阶段状态传递与连接历史
 S_LOCATE -> S_CLAMP -> S_JOIN -> S_RELEASE


 x_s^- = Phi_s(x_(s-1)^+, controls_s, parameters_s)
 Delta x^(s) = x_s^+ - T_(s-1->s) x_(s-1)^+
 lock_JOIN = {joint_ids, locked_reference_dofs, locked_reference_values, preload_actual,
 joint_stiffness}


每条 StageTransitionRecord 必须同时记录激活/撤除的边界、载荷和连接变化。JOIN 生成

LOCK_HIST_MULTIPART；RELEASE 撤除夹具边界和夹持载荷，但保留四个 JointDefinition。


阶段              边界/载荷变化                              接触活动点       继承要求

7 多零件误差链和贡献账本
 Delta y_KCP = sum_i J_SMS,i delta_SMS,i
             + sum_s sum_e J_e^(s) Delta gamma_e^(s)
             + J_process e_process


零件索引 i 覆盖 4 个 Part；接口索引 e 覆盖 4 个 Interface；阶段索引 s 覆盖 LOCATE、CLAMP、JOIN

和 RELEASE。ContributionRecord 的唯一键同步修订为：

 sample_id + source_class + source_id + origin_stage_id + increment_definition_id


本案例账本包含 4 条零件 SMS 绝对贡献和 12 条接口阶段增量贡献，总计 16 条。

KCPPredictionResult.predicted_values 可由这 16 条记录逐项求和重构。

11 软件执行流程（替换原 14.2 相关步骤）
 graph = load_assembly_graph(I0)
 layout = load_vector_layout('VL_CONTACT_ALL_12')
 state = initialize_part_and_interface_states(graph, layout, sms_packages)
 for stage in [LOCATE, CLAMP, JOIN, RELEASE]:
     active = graph.active_subassembly(stage)
     q = assemble_global_q(active.interfaces, state, stage, layout)
     W_struct = load_condensed_operator(stage, topology_hash, layout)
     W_total = W_struct + assemble_interface_compliance(active.interfaces, layout)
     solution = solve_global_lcp(q, W_total, warm_start=state.contact_mode)
     state = update_part_interface_and_aggregate_states(state, solution)
     if stage == JOIN: save_connection_lock_history(state)
     if stage == RELEASE: apply_retained_joints_and_compute_rebound(state)
     ledger.register_unique(stage_interface_increments(state))
 check_no_double_count(ledger)

12 最小案例验收标准

多零件最小案例只有同时满足以下条件，才可替代原 2 零件占位案例作为软件集成基准：

  至少 3 个零件、2 个接口；本案例为 4 个零件、4 个接口。

  同时存在一条长度不少于 2 的串联路径和两条连接同一端点的并联路径。

  至少一个柔性零件被两个以上接口共享。

  全局 W 包含非零交叉块；改变一个接口的 q 或载荷会改变另一接口结果。

  JOIN 有非零连接刚度或锁定位移，RELEASE 继承该历史。

  直接 KCP 提取与 ContributionLedger 重构一致。

  所有自动质量门通过，且合成/工程真实性标签明确。

附录 B 数据真实性说明

 重要限制：本数据包的拓扑、矩阵和结果均为合成数值一致性数据。它证明数据结构和算法接口能够连

 通，但不证明飞机垂尾翼盒或任何实际装配体的精度、载荷、柔度、接触压力或失效概率。工程使用前

 必须替换 CAD/网格、材料、SMS、边界载荷、W_struct、界面参数和验证数据。
